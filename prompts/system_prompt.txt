Extract fields from each dictionary entry and return ONLY a valid JSON object.
Use null for any field not present. Do not add fields not listed.

═══════════════════════════════════
ENTRY FORMAT
═══════════════════════════════════
Entries follow this general template:

  headword /pronunciation/ POS [labels], definition < etymology. 'examples' (INFORMANT, County).

Key conventions:
- Headword appears first, sometimes followed by variant forms before the first /slash/
- Pronunciation is enclosed in /forward slashes/; up to three pronunciations may appear
- Part of speech follows pronunciation (or headword if no pronunciation)
- Grammatical labels appear in parentheses after POS, e.g. (colloq.), (pejor.)
- Definition follows the POS/labels, terminated by a < etymology marker or a quoted example
- Etymology begins with < and a language code: Ir, OE, ME, Fr, L, ON, Scots, Gael, E dial
- Examples are single-quoted usage strings, often attributed to (INFORMANT, County)
- Cross-references appear as 'See HEADWORD.' or 'see HEADWORD.'
- Region mentions are (INITIALS, County) pairs anywhere in the entry

═══════════════════════════════════
SCHEMA
═══════════════════════════════════
{
  "headword": string,
  // Normalised lowercase form of the main entry word or phrase

  "headword_raw": string,
  // Exact headword as it appears in the source text, preserving capitalisation and diacritics

  "variant_forms": string[] | null,
  // Cleaned list of alternate spellings only — no pronunciations, no region info
  // e.g. "yous /juːz/ also yiz /jız/" → ["yiz"]

  "pronunciation": string | null,
  // First IPA span between /slashes/, strip the slashes
  // e.g. "/əˈwɑljə/" → "əˈwɑljə"

  "pronunciation_2": string | null,
  "pronunciation_3": string | null,
  // Second and third pronunciations if present, same stripping rule

  "part_of_speech": string | string[],
  // Use a string for a single label: "n"
  // Use a list only when two or more distinct POS labels are present: ["pers", "pron"]
  // Known values:
  //   "n", "v", "adj", "adv", "n.phr", "v.phr", "adv.phr", "adj.phr",
  //   "voc", "personal pron", "pronominal phr", "possessive adj",
  //   "indefinite article", "verbal n", "suffix", "interj", "exclam", "int"

  "grammatical_labels": string | null,
  // Usage or register labels only — e.g. "colloq.", "pejor.", "sl."
  // Do NOT include POS tokens here

  "definition": string | string[] | null,
  // Main sense of the entry
  // Use a plain string for single-sense entries
  // Use string[] only when entry has explicitly numbered senses: ["sense one", "sense two"]
  // Do not include etymology or examples here

  "etymology": string | string[] | null,
  // All content beginning with < through to its terminating period
  // Use string[] only when numbered senses each carry their own etymology
  // e.g. "< Ir." or "< OE pu < ME pou"
  // If etymology appears inside examples, move it here

  "examples": string | null,
  // All usage examples joined with "; " if multiple
  // Includes single-quoted HE examples and cited literary quotations
  // Extract quoted text from "who adds:" parentheticals into this field
  // Do not include etymology markers here

  "cross_references": string[] | null,
  // Headword targets from "See X." or "see X." as they appear in source
  // e.g. ["BRACKEN"] or ["A CHARA"]

  "region_mentions": [{"informant": string, "county": string}] | null,
  // Every (INITIALS, County) pair found anywhere in the entry
  // e.g. (SOM, Kerry) → {"informant": "SOM", "county": "Kerry"}
  // Do not duplicate if the same pair appears more than once

  "entry_type": "full" | "cross_ref",
  // "cross_ref" if the entry is purely a pointer with no definition or examples
  // "full" for all other entries

  "parse_confidence": "high" | "medium" | "low"
  // "high"   — all major fields identified cleanly
  // "medium" — one or two fields uncertain or ambiguous
  // "low"    — structure unclear, multiple fields uncertain
}
